# KOKO v0.5.0 — 실행 및 동기화 사용법

이 ZIP은 Windows에서 `npm install` 후 실행하는 **Electron 소스 프로젝트**입니다. EXE 설치 파일은 포함하지 않습니다. 메인 UI는 1440×900 기본, 최소 800×600, 최대 1920×1080 CSS 픽셀 범위에서 크기 변경 가능합니다(실제 디스플레이 작업 영역에 따라 제한됨).

## 1. 실행

1. 압축 안의 `KOKO_WORK` 폴더를 `C:\KOKO_WORK`와 같이 영문 경로에 풉니다. `renderer\pet.html`과 `package.json`이 존재해야 합니다.
2. 기존 KOKO가 실행 중이면 트레이 메뉴에서 종료합니다. (동일 앱의 중복 실행은 금지됩니다.)
3. CMD에서 `npm install`, `npm test`를 실행합니다.
4. `RUN_DEMO.cmd` 또는 `npm run demo`: **로그인/서버/실제 업로드가 없는 UI 시연**입니다.
5. `RUN_KOKO.cmd` 또는 `npm start`: **실제 OAuth 및 API 연동**입니다. 공개 API origin 기본값은 `https://capstone.nsu-coco.online`이며, `/docs`는 서버 문서입니다.

## 2. 이번 버전 핵심 작업

- **실행 중 변경 감지:** 사용자가 '업로드 + 이 폴더 자동 동기화'에 명시적으로 동의한 폴더만 `fs.watch`로 감시합니다. 운영체제에서 실시간 감시가 불가능한 경우에도 주기적으로 재탐색합니다.
- **재시작 후 재탐색:** 동의 내역과 마지막 처리한 파일의 크기·수정시간 서명을 앱 사용자별 저장소에 기록합니다. 로그인 복원 후 동의된 폴더만 재탐색해 신규·수정 파일의 R2 업로드를 시도합니다. 재시작해도 자동 동기화 동의를 새로 추정해 활성화하지 않습니다.
- **실패 처리:** 네트워크·5xx·429 등 일시적 오류는 제한된 횟수(최대 3회) 재시도합니다. 영구적 4xx는 무한 반복하지 않고 기록합니다. 설정의 '변경 사항 다시 검사'로 수동 재시도할 수 있습니다. 문서 서버 상태가 `processing_failed`이면 **해당 버전의 `upload-complete` 재호출**, `upload_failed`이면 **원본 재업로드 재시도** 버튼을 제공합니다.
- **상세 상태:** 서버 `GET /api/v1/documents/{id}`에서 최신 버전·상태·오류 코드를 조회합니다. 단, 상세 서버 응답 필드는 팀 Swagger와 최종 확인이 필요합니다.
- **삭제 안전 정책:** 파일 삭제·이동·이름 변경으로 원래 위치에서 사라진 문서는 **서버 DELETE 호출 없음**. 설정에 해당 경로를 기록하고 서버 원본/R2/DB 기록을 보존합니다. 변경된 새 이름 파일은 신규 문서로 업로드될 수 있으므로 서버에는 이전·새 문서가 함께 남을 수 있습니다. 영구 삭제 정책은 팀 승인 전까지 자동화하지 않습니다.
- **원본 동의:** 최초 저장 시 '취소', '이번에만 업로드', '업로드 + 이 폴더 자동 동기화' 중 하나를 선택합니다. 자동 동기화는 기본 **OFF**입니다. 설정의 '자동 동기화 중지'로 향후 자동 전송을 중단합니다.

## 3. UI 동선

- 코코 펫 클릭 → 미로그인 시 로그인, 로그인 상태면 메인 작업실
- 파일 감지 → Windows 폴더 선택 → X 제외/복구 → 저장 시작 → 동의창에서 이번 1회/자동 동기화 선택 → R2 업로드 → AI 분석 요청 및 상태 조회
- 작업실 → **설정** → 자동 동기화 상태/최근 검사/오류/사라진 로컬 문서 확인/변경 사항 다시 검사/동기화 중지
- 저장 결과 → 실패 항목에서 **상세 상태**, **재시도** 버튼 확인. `ready`일 때만 다운로드 버튼 노출

## 4. 데이터·보안 구분

- `RUN_DEMO.cmd`: 시연 전용, OAuth 미실행, 실제 서버 전송 없음, 예시 알림과 예시 UI.
- `RUN_KOKO.cmd`: 실제 API 모드; 소셜 로그인, 사용자 폴더 선택 및 업로드 동의가 있어야 파일 전송 가능.
- 기기 ID, 로컬 폴더 동의 및 마지막 처리 정보는 Electron `userData` 폴더에 계정/서버별로 저장됩니다. 로그인 토큰은 기존 암호화 안전 저장 방식 유지. SSH·DB 비밀번호는 포함되지 않습니다.
- 자동 감시는 폴더가 열릴 때만 동작하는 UI 기능이 아니라, **실제 KOKO 앱이 실행되고 로그인되어 있는 동안** 동작합니다. 앱이 완전히 꺼져 있으면 업로드하지 않으며 다음 로그인 복원 때 변경 사항을 검사합니다.
- 제외된 하위 파일은 업로드하지 않습니다. 심볼릭 링크, 숨김 파일/폴더, `node_modules`, `.git` 등 기본 제외 경로는 스캔하지 않습니다. 5,000항목·12단계 초과 폴더 및 100MB 초과 파일은 업로드 대상에서 제한됩니다.
- 현재 동기화 기록은 크기·수정시간 비교에 의존하므로, 파일 내용이 바뀌어도 크기와 수정 시간이 모두 동일하게 보존된 특수한 변경은 감지하지 못할 수 있습니다.
- 새 버전은 수동 동기화를 완료한 폴더에만 자동 동기화를 선택할 수 있습니다. 수동 업로드 진행 중에는 해당 폴더 감시가 잠시 일시정지됩니다.

## 5. 검증 범위 및 남은 이슈

- `npm test` 자동 검증: 기존 OAuth·문서 API + 자동 동기화 신규 테스트.
- **모의 API 기반 테스트**가 통과한 것이며, 실제 KOKO 팀 서버에서 OAuth/R2/AI 업로드 성공은 아직 검증되지 않았습니다.
- AI 의미 검색·실제 알림 추천 API는 연동 완료로 표기하면 안 됩니다.
- 폴더가 5,000항목 이상이거나 장시간 쓰기 중인 파일, 대량 변경, 네트워크 단절, 서버 API 응답의 실제 버전 필드 등은 Windows 현장 통합 테스트에서 검증해야 합니다.
- 사용자가 동의를 철회하더라도 **이미 R2에 업로드한 파일은 삭제하지 않습니다.** 필요 시 별도의 삭제/개인정보 정책을 마련해야 합니다.

팀 실제 서버 통합 테스트 단계는 [`docs/TEAM_INTEGRATION_TEST_V05.md`](docs/TEAM_INTEGRATION_TEST_V05.md)를 참고하세요.
