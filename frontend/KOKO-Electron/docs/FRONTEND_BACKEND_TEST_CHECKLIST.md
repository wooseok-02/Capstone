# KOKO — 프론트엔드/백엔드 연동 테스트 체크리스트 (정태구 담당자 협업용)

검증자: 프론트엔드 담당 + 정태구 담당자 / 날짜: 미정 / 백엔드 BASE URL: 팀에서 제공 필요

## 1. 사전 준비
- [ ] 서버 BASE URL 및 테스트 서버 환경 공유. 접근 권한과 계정 확인.
- [ ] Google OAuth 등록, Electron 루프백 인증 경로 테스트.
- [ ] 테스트용 폴더 준비 (개인정보 없는 .md/.txt/.pdf 등). R2 개발 버킷 분리.
- [ ] 개발용 계정의 Access/Refresh Token이 유효한지 확인.
- [ ] 테스트 파일 삭제가 서버의 R2 원본을 삭제할 수 있으므로 삭제·이동 테스트는 별도 승인.

## 2. 파일 등록 테스트
- [ ] 최초 기기 등록 POST /api/v1/devices: UUID 발급, 다음 실행 시 재사용.
- [ ] 동일 PC 다른 소셜 계정: device_id가 서로 혼용되지 않음.
- [ ] 폴더 등록 POST /api/v1/folders: 새 폴더 ID 발급.
- [ ] 같은 폴더 중복 등록 409: 기존 folder_id 반환.
- [ ] 이미 등록한 폴더와 상위·하위 경로 중복 연결 방지.
- [ ] 트리의 파일/폴더 제외(X) 및 복구 → `excluded_paths` 전체 목록 교체.
- [ ] 경로는 `폴더 기준/상대 경로`, 역슬래시/절대 경로 미전송.

## 3. 문서 업로드 + 분석 테스트
- [ ] 파일 정보 POST /api/v1/documents: SHA-256과 크기 확인.
- [ ] upload_url 발급 시 R2 PUT 완료 (`upload_headers` 동일, Authorization 없음).
- [ ] upload_url=null인 중복 파일은 재업로드하지 않음.
- [ ] POST /upload-complete 후 AI 서버에서 상태가 `processing` → `ready` 변화.
- [ ] UI에 업로드 완료 / AI 분석 완료 개수 분리 표시.
- [ ] 100MB 초과(413), 제외 파일 전송(422), 권한 없음(401/404), R2 오류(502), AI 실패(503) 확인.
- [ ] AI 처리 실패 메시지가 원인 코드 `error_code`와 연결되는지 확인.
- [ ] GET /api/v1/folders/{id}/documents 실 응답의 배열 위치 및 최신 버전 상태 필드 확인.
- [ ] 서버 진행 상태 5초 폴링 표시와 앱 전환 시 동작 확인.

## 4. 알림 추가 API 필요 (명세 미제공)
- [ ] AI 추천/알림 목록 조회 API와 페이징·필터 명세 공유.
- [ ] 알림 읽음 상태 PATCH 또는 POST API 명세 공유.
- [ ] 추천 연결 이유, 인용 근거, 원본문서 접근 권한 정책 확정.
- [ ] 로컬 원본 열기와 R2 다운로드/재다운로드 여부 확정.
- [ ] 실제 API 연결 이전에는 알림 화면의 모든 항목을 '예시'로 표시.

## 5. 미구현 범위 / 별도 결재
- [ ] 폴더 변경 감지(실시간 추가·수정, 재실행 시 재탐색) 개발 작업 배정.
- [ ] 파일 삭제/이동 시 R2 및 DB 영구 삭제 정책 합의 (자동 삭제 즉시 활성화 금지).
- [ ] 민감정보 서버 업로드 동의, 개인정보 처리 방침, 지원 파일 형식 확정.
