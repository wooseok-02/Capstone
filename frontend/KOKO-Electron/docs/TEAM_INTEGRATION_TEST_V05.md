# KOKO v0.5.0 — 팀 백엔드 통합 테스트 체크리스트

> **실제 백엔드 테스트는 사용자/팀원이 Windows + 팀 OAuth 계정으로 수행해야 합니다.** 이 파일은 체크리스트이며 서버 테스트 성공 보고서가 아닙니다.

## 환경

- 원격 API origin: `https://capstone.nsu-coco.online` (비밀번호나 운영 SSH 인증 필요 없음)
- 서버 API 명세: `https://capstone.nsu-coco.online/docs`, 실제 명세 경로/응답 구조 비교
- 민감한 정보는 GitHub/프론트 번들/디버그 로그/채팅에 입력하지 않습니다.
- 개발용 빈 테스트 폴더로 시작합니다. 개인자료·과제·비밀파일 업로드 금지.

## 실서버 필수 확인

- [ ] Google 또는 사용 가능한 OAuth로 로그인 → `/me` 확인 → 코코 펫 클릭 작업실 열림
- [ ] 신규 기기 등록 1회만 발생, 재실행해도 같은 `device_id` 사용
- [ ] 테스트 폴더 등록 및 기존 폴더 재등록 409 처리; 상·하위 중복 폴더 방지
- [ ] `excluded_paths` 상대 경로만 서버로 전달; 제외된 파일 업로드 없음
- [ ] `POST /documents` 응답의 Presigned URL 사용, R2 PUT에 Bearer 미포함, 제공된 upload_headers 정확히 적용
- [ ] `POST /upload-complete` 이후 `uploaded / processing / ready` 각각 UI 표시 확인
- [ ] 실패 상세 `GET /documents/{id}` 응답에서 문서 버전 및 오류 코드 확인
- [ ] 실제 AI 분석 실패 `processing_failed`에 해당 버전 `upload-complete` 재요청 검증
- [ ] 업로드 실패 `upload_failed`에 다시 등록하여 신규 URL 발급 후 R2 PUT 검증
- [ ] 자동 동기화 선택 **안 했을 때** 파일 생성·수정 후 자동 업로드 없음
- [ ] 자동 동기화 선택 후, 새 파일 작성 / 기존 파일 수정 → 자동 업로드
- [ ] 실행 중 파일 수정·저장 연속 이벤트가 여러 번 와도 불필요한 중복 문서 폭증 없음
- [ ] 코코 완전 종료 중 파일 수정 후 재실행·자동 로그인 → 변경 파일 다시 업로드
- [ ] 로컬 파일 삭제·이름 변경 후에도 서버 DELETE 호출 없음, 서버 원본 남음
- [ ] 설정에서 자동 동기화 중지 후 파일 수정해도 업로드되지 않음
- [ ] 401 만료 토큰·403 서명 URL 오류·429·502·503·네트워크 단절에서 적절한 오류 표기
- [ ] Windows 100%/125% 배율로 800×600 / 1440×900 / 1920×1080 화면 검증
- [ ] 코코 펫 오른쪽 클릭·좌클릭 / 로그인 전후 / 로그아웃 / DEMO 모드 회귀 확인

## 아직 미구현 또는 팀 합의 필요

- 자동 서버 삭제/이동 동기화: **기본 비활성**, 사용자 보호 정책 확정 전 구현 금지
- 실제 알림 조회·읽음·추천 근거 데이터: 팀 알림 API 최신 Swagger 명세가 필요한 단계
- 서버 AI 검색어 임베딩 API가 준비되었는지 별도 확인
- 마이그레이션: 이전 앱에서 이미 등록된 폴더에 자동 동기화 동의를 추정하지 않음
